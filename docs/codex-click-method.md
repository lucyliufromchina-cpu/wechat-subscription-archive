# 用 Codex（Computer Use）逐篇点开文章：操作规程

> 由 Codex 在 2026-10-05 实跑后记录，经整理去掉了具体公众号。适用于本 skill 的主方法：微信客户端打开文章 → 本机代理旁听 → 直存。

本文记录 2026-10-05 在 macOS 微信内置浏览器中实际跑通的点击采集方法。目标是让微信客户端正常请求公众号历史文章页面，由本机代理旁听请求；Codex 不复制链接、不读剪贴板，也不伪造微信请求。

## 1. 前置

- 已验证的客户端是 macOS 微信 `4.1.13`（build `269631`，bundle id `com.tencent.xinWeChat`）。微信升级后，标签页、返回按钮和卡片位置都可能变化，必须先用一篇文章复测。
- 微信已登录。打开目标公众号资料页，进入“全部消息”，切换到“文章”列表。
- 必须使用微信内置浏览器，不要改用 Chrome。若内置页与聊天窗口合并，点击内置浏览器右上角的“独立窗口/弹出”按钮，将它变成独立窗口。实际验证时窗口标题为 `WeChat (Window)`。
- 独立窗口开始运行后不要再移动、缩放或最大化。用户也不要同时移动鼠标、滚动列表或切换标签页，否则截图坐标会失效。
- 本方法依赖的代理前提：
  - `mitmdump` 正在 `127.0.0.1:8899` 监听，并加载 `scripts/wechat_sniff.py`；
  - 系统 HTTP/HTTPS 代理均指向 `127.0.0.1:8899`；
  - `~/.mitmproxy/mitmproxy-ca-cert.pem` 已加入系统钥匙串并被信任；
  - 修改代理或证书后已重启微信；
  - 只旁听 `mp.weixin.qq.com`，不修改请求、不绕过验证码或账号风控。
- 可另开进程运行 `python3 scripts/wechat_links.py sniffed` 消费旁听队列。点击流程的成功标准是代理记录到请求/队列新增，不只是鼠标脚本打印 `completed`。

## 2. 循环

### 定位方式

以截图识别为主，不依赖辅助功能树定位文章。当前微信版本的辅助功能树只能稳定看到窗口、菜单栏等外壳，看不到公众号日期、标题和卡片，因此不能按 AX 元素编号点击文章。

辅助功能只用于两件事：确认目标窗口标题为 `WeChat (Window)`，以及读取窗口左上角原点。文章卡片、主卡和次卡都从最新截图中识别，再换算为窗口内逻辑坐标点击。

Retina 屏幕要注意缩放：本次截图是 `1840 × 1640` 像素，对应窗口逻辑坐标约 `920 × 820`。例如截图上的卡片中心约为 `(920, 1000)`，鼠标脚本应点击约 `(460, 500)`。窗口尺寸变化后必须重新测量，不能沿用旧坐标。

### 每篇文章的动作

1. 在列表截图中找卡片中心并点击。一次推送里的主卡和每一张次卡都是独立文章，必须分别点击。
2. 固定等待 `2 秒`。这段时间用于让文章标签页和网络请求建立；当前实现不是 DOM/事件驱动，也没有可靠的 AX 加载完成信号。若两秒后仍未出现文章标签或页面明显空白，再等待最多两秒并停止当前批次检查，不要连续盲点。
3. 返回列表并清理文章标签页。实际最稳的顺序不是直接关闭当前文章页，而是：
   1. 点击仍然保留的“公众号文章列表”标签页；
   2. 等待 `0.5 秒`；
   3. 点击文章标签页一次，使它成为活动标签页；
   4. 等待 `0.35 秒`；
   5. 在同一位置再点一次，关闭已激活的文章标签页；
   6. 等待 `1.15 秒`，确认列表仍在原来的滚动位置。
4. 处理当前屏幕内其余卡片。每批建议只处理 `3–5` 张，随后重新截图校验。
5. 当前屏幕处理完后，按目标时间方向滚动一屏，再重新截图定位：
   - 从新到旧抓历史文章：向下滚；
   - 从旧到新补近期文章：向上滚。

在本次固定窗口中，曾验证可用的逻辑坐标是：列表标签页约 `(280, 21)`，文章标签页清理点约 `(598, 21)`，卡片列中心 `x ≈ 460`。这些只是本次窗口的测量值，不是跨机器常量。

如果文章是在同一标签页内打开、没有生成第二个标签页，才使用工具栏左上角返回箭头（本次约 `(95, 21)`）回到列表。返回后必须通过截图看到公众号列表的日期和卡片，不能只根据一次点击推断成功。

## 3. 节奏

- 实测稳定速度约为 `5.6–5.8 秒/篇`。其中包含：文章打开后等待 2 秒、切回列表、激活并关闭文章标签页、恢复等待。
- 3 篇一批约 17.5 秒，4 篇一批约 23 秒，5 篇一批约 28.8 秒。
- 当前点击器使用固定间隔，没有随机抖动。不要为了提速把单篇压到 4 秒以内；微信以登录账号发起请求，过快可能触发账号级频控。
- 每批结束都重新截图，比一次提交很多坐标更可靠。批次越大，页面加载、窗口焦点或误点造成的坐标漂移越难恢复。

## 4. 异常

### 出现弹窗或验证页

- 普通信息弹窗遮挡列表时，暂停批次，先截图确认内容，再关闭明确无风险的提示。
- 遇到登录、账号验证、验证码或 `secitptpage/verify`，立即停止并交给用户处理；不尝试绕过，也不要继续密集点击。
- 旧的“Copy Link / 已保存”流程已经停用，不需要打开三点菜单，也不等待剪贴板通知。

### 页面没有回到列表

1. 立即停止当前批次并截图，不再执行后续卡片坐标。
2. 如果列表标签页仍在，先点列表标签页，再处理文章标签页。
3. 不要直接关闭当前活动文章标签页；这曾导致列表标签页一起丢失或出现空白窗口。
4. 如果文章与列表在同一标签页，点左上角返回箭头并等待；必须看到日期、标题和卡片后才能继续。
5. 如果只剩空白页或列表标签已丢失，从公众号资料页重新进入“全部消息 → 文章”，再按续点方法恢复。

### 屏幕锁定或休眠

- 锁屏后鼠标事件可能被脚本发出，但微信不会实际完成点击；终端中的 `completed` 不能证明成功。
- 停止点击，解锁屏幕并保持常亮。重新截取微信独立窗口，确认当前日期、卡片和标签页状态后再续跑。
- 长批次运行前应关闭自动锁屏或使用系统允许的防休眠方式；不要在屏幕已经黑掉时继续计数。

### 代理异常

- 如果 `mitmdump` 停止但系统代理仍指向 `127.0.0.1:8899`，微信请求可能直接失败。
- 如果系统代理已关闭，页面可能还能打开，但 `wechat_sniff.py` 收不到请求。
- 发现点击无新增记录时先暂停，检查代理进程、系统 HTTP/HTTPS 代理和证书，再重启微信并用一篇文章做端到端验证。不要用重复猛点来“补救”。

## 5. 续点

- 每批完成后记录四项：公众号、滚动方向、最后确认处理的日期与标题、当前屏截图。可把文字进度同步到 `<归档目录>/_进度.md`。
- 中断恢复时，从公众号“文章”列表找到上次的日期和标题。为避免漏掉中断时正在打开的文章，回退一屏并把该屏全部重新点一遍；后端按 `biz + mid + idx` 去重，少量重复比漏抓安全。
- 同一天的主卡和次卡要逐一核对。不能因为日期相同或图片属于同一次推送，就把次卡当成已处理。
- 判断已经到最早一篇，需要同时满足：
  1. 向下滚动条已经到达底部；
  2. 再向下滚一次，截图中的日期和最后一张卡片不再变化；
  3. 没有出现更早日期；
  4. 最后一组推送的所有主卡和次卡均已点击。
- 判断已经到最新一篇时，向上滚到公众号资料头部重新出现，滚动条位于顶部，并且再次向上滚不再出现更新卡片。本次任务就是以公众号资料头部重新出现作为到顶校验。

## 6. 已知坑

- **锁屏不是“只是看不到”**：昨晚屏幕锁定期间，点击实际上没有可靠执行。恢复后必须从上一个已确认批次续点。
- **代理停掉会造成假进度**：脚本仍可能输出 `completed`，但代理没有记录到文章请求。必须用队列/日志新增作为采集成功证据。
- **合并窗口会漂移**：微信聊天窗口与内嵌页合并时，窗口位置、尺寸和工具栏布局会变化。弹成独立窗口后再固定坐标，稳定性明显更高。
- **不要直接关活动文章标签页**：此前把文章标签页的关闭位置当“返回”点，加载慢或误点时会关闭错误标签，最后只剩白屏。修复方法是先切回列表标签页，再激活并关闭文章标签页。
- **辅助功能树看不到卡片**：不能反复等待 AX 出现标题；应使用最新截图定位卡片，AX 只辅助找窗口。
- **Retina 坐标不是截图像素**：截图像素坐标通常要除以 2 才是鼠标逻辑坐标。窗口尺寸或显示缩放变化后重新标定。
- **用户同时操作会打断流程**：移动鼠标、滚动、切换窗口、与 Codex 对话造成窗口失焦，都可能让预定坐标点到别处。运行批次时应暂时不操作电脑。
- **部分露出的卡片容易误点**：优先把卡片滚到可见中心再点；若必须点击边缘，只点明确位于内容区的可见部分，避开顶部标签栏和底部边界。
- **一屏坐标不能跨屏复用**：每次滚动后重新截图、重新算卡片中心。每批 3–5 篇并校验列表仍在，是速度和稳定性的折中。
